# RFC-016: Addressability

Status: Draft

## Purpose

Определить нормативный способ адресации элементов Semantic Core посредством
Hierarchical Identifier Path (HIP).

## Scope

Документ определяет форму нормативного идентификатора адресуемого элемента и
его инварианты. Внутренние идентификаторы и алгоритмы разрешения путей остаются
вопросом реализации.

## Definition

Canonical definitions: DEF-010 (Addressability), DEF-009 (Hierarchical
Identifier Path).

Addressability — свойство семантического элемента, позволяющее однозначно
ссылаться на него в пределах Semantic Model посредством его нормативного
идентификатора (DEF-010).

Hierarchical Identifier Path (HIP) — упорядоченный иерархический путь,
однозначно адресующий один семантический элемент в пределах Semantic Model
(DEF-009).

Полный HIP является нормативным идентификатором элемента. Отдельные сегменты
образуют путь от пространства модели к конкретному элементу; синтаксис и
кодирование сегментов настоящим RFC не устанавливаются.

## Normative Requirements

AD-001 Каждая Entity и каждый Statement Instance должны иметь полный HIP.

AD-002 Полный HIP должен однозначно адресовать ровно один элемент в пределах
данной Semantic Model.

AD-003 HIP элемента должен быть устойчивым, пока элемент сохраняется в данной
Semantic Model.

AD-004 Addressability и HIP не определяют семантическую идентичность элемента.

AD-005 HIP должен сохраняться при преобразовании между внутренним
представлением и Canonical Text, а также при производном преобразовании между
Canonical Text и Canonical Diagram.

AD-006 Реализация может использовать любые внутренние идентификаторы, ключи,
указатели или индексы. Они не являются частью Semantic Core и не могут заменять
HIP в каноническом представлении модели.

AD-007 Два элемента с различными HIP считаются различными элементами Semantic
Model, пока Theory явно не установит их семантическую идентичность посредством
Statement Instance.

AD-008 Утверждение семантической идентичности не должно изменять, объединять
или устранять HIP участвующих элементов.

## Non-goals

- глобальная уникальность между независимыми Semantic Model;
- обязательный синтаксис или кодирование сегментов HIP;
- алгоритм генерации HIP;
- относительные пути и правила их разрешения;
- жизненный цикл и переименование HIP;
- внутренние ключи, индексы и структуры хранения;
- распределённые системы.

## Rationale

HIP задаёт единый нормативный адрес элемента и одновременно сохраняет
иерархическую структуру пространства имён. Полный путь является достаточным
критерием адресации; дополнительные идентификаторы Core не требуются.

Разделение HIP и внутренних идентификаторов позволяет реализациям свободно
выбирать структуры хранения и поиска, не изменяя переносимую семантическую
адресацию. Презумпция неидентичности сохраняет элементы раздельно, даже когда
Theory утверждает их семантическую идентичность.
