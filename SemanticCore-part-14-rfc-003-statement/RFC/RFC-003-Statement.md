# RFC-003: Statement

Status: Draft

## Purpose

Определить семантический примитив Statement.

## Scope

Документ описывает только семантику Statement.

## Definition

Canonical definition: DEF-004.

Statement определяет тип семантического отношения и полный набор допустимых
Role. Statement индивидуально адресуем и может использоваться как Value, что
позволяет обычным Statement Instance ссылаться на само определение отношения.
В базовом механизме Semantic Core семантика отношения принадлежит Statement;
конкретные Statement Instance только выражают эту семантику для назначенных
Values. Core рассматривает Statement как целостное определение отношения и не
выделяет внутри него отдельный нормативный Predicate.

## Normative Requirements

ST-001 Statement определяет множество Role.

ST-002 Каждый Statement рассматривается как отдельное определение отношения.
Совпадение структуры двух Statement само по себе не устанавливает их
семантическую идентичность.

ST-003 Statement сам по себе не содержит значений Role.

ST-004 Значения появляются только в Statement Instance.

ST-005 Statement может иметь любое количество Role.

ST-006 Statement является единственным примитивом базового механизма Semantic
Core, который задаёт семантику отношения. Role и конкретные Value не могут
самостоятельно переопределять эту семантику.

ST-007 Каждый Statement должен иметь устойчивый полный HIP, однозначно
адресующий его в пределах Semantic Model.

ST-008 Statement может использоваться как Value. Такое использование не
изменяет семантику отношения, определённую этим Statement.

ST-009 Semantic Core не определяет отдельный Predicate как примитив или
обязательную составную часть Statement. Дополнительные семантические сведения о
Statement выражаются обычными Statement Instance либо средствами Theory.

## Non-goals

- порядок хранения;
- визуальное представление;
- ограничения Theory;
- теория семантической идентичности Statement;
- внутреннее представление отношения в конкретной реализации.

## Rationale

Statement описывает форму и семантику отношения, а не конкретный факт.
Statement Instance выражает конкретный факт, применяя семантику Statement к
Values через определённые им Roles. Поскольку Statement адресуем и сам может
быть Value, Theory может именовать, классифицировать и связывать определения
отношений обычными Statement Instance. Поэтому отдельный Predicate не даёт
новой выразительной возможности базовому механизму Core.

## Rejected Alternatives

### Separate Predicate primitive

Отклонено, поскольку после появления адресуемого Statement как Value требуемые
мета-утверждения о типе отношения уже выражаются существующими примитивами.
Выделение Predicate либо дублировало бы семантическую роль Statement, либо
создавало бы параллельный носитель семантики. Theory при необходимости может
моделировать понятие Predicate композиционно на уровне Theory, не изменяя
базовую структуру Core.
